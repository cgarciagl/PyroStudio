Actúa como un Arquitecto de Software Senior experto en desarrollo multiplataforma y bases de datos. Tu tarea es ayudarme a construir desde cero "Pyro Studio", un cliente de bases de datos moderno, ultraligero y de alto rendimiento para MariaDB, diseñado para competir con herramientas como Navicat y TablePlus.

El objetivo principal es que la aplicación no consuma los excesivos recursos de Electron, tenga una interfaz reactiva y maneje la importación/exportación masiva de Excel de manera impecable, ideal para procesar grandes volúmenes de datos institucionales (como listas de matrículas, índices, o registros de casos escolares) sin congelar la UI. También que permita hacer actualizaciones de datos en tiempo real sobre los resultados de consultas tal como lo permite Navicat.

### 1. Stack Tecnológico Estricto
Debes utilizar exclusivamente las siguientes tecnologías:
*   **Core/Backend:** Tauri v2 (Rust). Se encargará de la gestión de memoria, túneles SSH, conexión a MariaDB y lectura/escritura de archivos binarios.
*   **Driver BD:** Crates de Rust como `sqlx` (con soporte asíncrono y pool de conexiones) o `mysql_async`.
*   **Frontend:** React 19 + TypeScript + Vite.
*   **Estilos:** Tailwind CSS + componentes base de Radix UI o shadcn/ui.
*   **Editor SQL:** CodeMirror 6 o Monaco Editor.
*   **Data Grid:** Glide Data Grid (renderizado en canvas para soportar miles de filas a 60 fps sin colapsar el DOM).
*   **Manejo de Excel (Backend):** `calamine` para lectura rápida e importación; `rust_xlsxwriter` para exportación con formato nativo.

### 2. Reglas de Arquitectura e IPC
*   **Separación estricta:** El frontend es "tonto". Nunca debe procesar lógica pesada ni archivos masivos. Todo el procesamiento de datos, ejecución de queries y parsing de Excel ocurre en Rust.
*   **Comunicación:** Utiliza el sistema de comandos (IPC) de Tauri. Para consultas que retornen miles de registros, implementa paginación o streaming basado en cursores desde Rust hacia React.

### 3. Fases de Desarrollo Inicial (Plan de Acción)
Vamos a desarrollar esto por fases. Por ahora, solo genera la estructura base y pregúntame antes de pasar a la siguiente fase.

**Fase 1: Setup y Conexión Base**
*   Inicializa el proyecto Tauri + Vite + React.
*   Crea el comando IPC en Rust para establecer conexión con MariaDB (host, port, user, pass, database) usando `sqlx`.
*   Devuelve un listado de esquemas y tablas al frontend.

**Fase 2: Layout "Pyro" y Explorador**
*   Diseña el shell de la aplicación: Panel lateral izquierdo (árbol jerárquico de Base de Datos > Tablas) y panel principal con pestañas (Tabs).
*   El tema debe ser un "Dark Mode" profundo (grises muy oscuros, casi negros) con acentos en colores fuego (naranja neón o carmesí).

**Fase 3: Visualización de Datos (Data Grid)**
*   Implementa Glide Data Grid en React.
*   Conecta un comando de Rust que ejecute `SELECT * FROM tabla LIMIT 1000` y lo envíe al grid de manera fluida.

**Fase 4: La "Navicat Killer Feature" - Asistente de Excel (MUY IMPORTANTE)**
Debes diseñar la arquitectura para la importación y exportación de archivos `.xlsx` bajo estas reglas estrictas:
*   **Exportación Profesional:** Cuando el usuario exporte una tabla o resultado de consulta, Rust (`rust_xlsxwriter`) debe generar el `.xlsx` aplicando estilo a la primera fila (encabezados en negrita, color de fondo sutil) e inmovilizando los paneles superiores (Freeze Panes).
*   **Asistente de Importación (Stepper):**
    1.  **Preview:** El usuario selecciona el archivo. Rust lee solo las primeras 50 filas con `calamine` y las envía al frontend para previsualizar.
    2.  **Mapeo:** Interfaz en React donde se emparejan las columnas del Excel con las columnas de MariaDB (con opción de ignorar columnas).
    3.  **Modo:** Opciones para Insertar (Append), Actualizar (Update - definiendo llave primaria) o Reemplazar (Truncate + Insert).
    4.  **Ejecución:** Rust procesa el archivo completo en lotes (batches de 1000) usando transacciones. Si una fila falla (ej. tipo de dato incorrecto), se registra el error en un log interno pero la ejecución NO se detiene. Al final, se retorna un resumen (Éxitos vs. Errores).
